## 개발 단계

각 단계는 CLAUDE.md의 작업 방식(설계안 → 승인 → 구현 → 보고)으로 진행한다. 완료 조건은 설계안 작성 시 더 구체화한다.

### 1단계: 프로젝트 세팅
- [ ] Next.js + Tailwind CSS 프로젝트 생성
- [ ] Supabase 프로젝트 생성 및 연결 (`.env.local`)
- [ ] GitHub 저장소 연결, Vercel 자동 배포
- [ ] FullCalendar 설치

**완료 조건:** Vercel 주소에서 빈 페이지가 열리고, Supabase 연결 테스트가 성공한다.

### 2단계: DB + RLS
- [ ] 11개 테이블 생성 (`docs/decisions.md` 7장)
- [ ] RLS 정책 작성 (`docs/decisions.md` 8장)
- [ ] 좋아요 집계 뷰
- [ ] 시연용 명단, 과목 데이터 입력

**완료 조건:** 일반 사용자 권한으로 `student_roster` 조회 시 거부되고, 권한 규칙대로 조회·작성이 동작한다.

### 3단계: 회원가입·로그인 (F1)
- [ ] 가입 화면 (학번, 비밀번호, 복구용 이메일)
- [ ] 서버에서 학번 규칙·명단·중복 검사
- [ ] 이메일 인증
- [ ] 학번 로그인 (서버에서 이메일 조회)
- [ ] 비밀번호 재설정

**완료 조건:** 명단에 있는 학번은 가입되고, 없는 학번·중복 학번은 거부된다. 브라우저 네트워크 요청에서 명단 데이터가 보이지 않는다.

### 4단계: 전과·복수전공 승인 (F1, F7)
- [ ] 명단에 없을 때 승인 요청 화면 (유형 선택, 증빙 첨부)
- [ ] 승인 대기 안내 화면
- [ ] 관리자 승인·거절 화면 (거절 사유)
- [ ] 처리 후 증빙 이미지 삭제

**완료 조건:** pending 사용자는 캘린더에 접근할 수 없고, 승인 후 접근할 수 있다.

### 5단계: 수강 과목 선택 (F2)
- [ ] 이번 학기 과목 목록과 선택·해제

**완료 조건:** 선택한 과목의 일정만 캘린더에 표시된다.

### 6단계: 메인 캘린더 (F3)
- [ ] 월간·주간 전환
- [ ] 유형별 색상 (색상 결정 필요)
- [ ] 종일·시각 일정 구분 표시
- [ ] 우측 상단 등록 버튼

**완료 조건:** 휴강·공지는 종일 영역에, 과제·시험은 해당 시각에 표시된다.

### 7단계: 일정 등록 (F4)
- [ ] 등록 폼 (과목, 유형, 제목, 설명, 출처, 일시)
- [ ] 출처 링크·캡처 첨부
- [ ] 저장 직전 같은 과목·같은 날짜 중복 확인
- [ ] 첫 등록자만 수정

**완료 조건:** 등록 즉시 캘린더에 표시되고, 중복 날짜면 기존 일정 목록이 뜨며, pending 사용자는 API 직접 호출도 거부된다.

### 8단계: 일정 상세 (F5)
- [ ] 상세 화면 (구글 캘린더 참고)
- [ ] 일정 좋아요
- [ ] 댓글 작성·수정·삭제
- [ ] 댓글 좋아요, 최다 좋아요 댓글 상단 노출

**완료 조건:** 좋아요는 1인 1회만 되고, 최다 좋아요 댓글이 맨 위에 보인다.

### 9단계: 신고·문의·관리자 (F6, F7)
- [ ] 일정·댓글 신고
- [ ] 비로그인 문의 (스팸 제한)
- [ ] 관리자 페이지 (신고 처리, 숨김, 정지, 문의 처리)

**완료 조건:** 숨김 처리된 항목은 관리자에게만 보이고, 정지된 사용자는 작성할 수 없다.

### 10단계: 마무리
- [ ] 반응형 다듬기 (모바일 확인)
- [ ] PWA 설정 (홈 화면 추가)
- [ ] Claude + Gemini 교차 리뷰 및 반영

### 11단계: 추가 기능 (여유 시)
- [ ] 구글 캘린더 내보내기

### 12단계: 최종 발표 준비
- [ ] 시연 영상 (시나리오: 본전공 학생, 복수전공 학생, 정보 등록자, 틀린 정보 정정)
- [ ] 프롬프트 개선 사례, 트러블슈팅 사례, 교차 검증 결과 정리
